maw new vs wake vs work

Three commands for creating tmux workspaces in the maw-rs CLI. They overlap in surface but differ in intent: new scaffolds raw sessions, wake resolves oracles to repos and launches engines, work adds git worktree isolation on top. This reference covers every flag, compares capabilities, and provides copy-paste recipes.

Which Command to Use

  • You need a raw tmux session or split pane with a shell or custom command → maw new
  • You want to launch Claude in a new session with env vars wired up → maw new --claude
  • You know the oracle name and want to wake it with the right engine → maw wake
  • You need to wake an oracle on a remote fleet peer → maw wake --peer
  • You want isolated agent work with a git worktree per coder → maw work --wt
  • You want to spawn N codex coders on separate branches → maw work . task --wt -e codex
  • You have a GitHub URL and want to clone + work on it → maw work <url>
  • You need a split pane in the current window → maw new --split

maw new

Worktree Support

Not supported. maw new does not create or manage git worktrees.

Engine Support

No --engine flag. When --claude is used, calls workon_build_command_in_dir to resolve the configured engine from .maw config. Falls back to bare claude if the resolved command does not look like a claude command.

Tmux Interaction

Session mode: checks has-session, creates detached via new-session -d -s name -n window -c cwd. Stores launch context as @maw_new_cwd / @maw_new_command / @maw_new_window session options. Collision: auto-increments suffix up to 99.
Split mode: calls split-window -f -h/-v, sets pane title via select-pane -T.

maw wake

crates/maw-cli/src/core_impl/wake.rs — usage L294, entry L121, args L162

Resolves an oracle name to a repo path (via ghq roots and fleet entries, with fuzzy matching), creates or reuses a tmux session/window at that repo, sends an engine launch command into the pane, and auto-registers in the fleet registry. For remote peers (containing ":" or --peer), delegates to run_wake_async which sends the request over HTTP to a remote maw serve node.

Worktree Support

--wt takes a slug used to derive the tmux window name as {oracle}-{wt_slug}. Takes priority over --task for naming. The slug is sanitized to alphanumeric + hyphens. Does not create git worktrees itself — that is handled upstream by callers like team up.

Engine Support

Resolution order: (1) --engine value if set. (2) --resume forces "codex". (3) Merged .maw config commands.default. (4) Fallback: "codex". Engine name is resolved through wake_resolve_engine_command() which expands custom engines from the config commands map (e.g. "omx-1" becomes its full shell command).

Tmux Interaction

Uses WakeTmuxNative trait backed by TmuxClient::local(). Lists existing sessions, resolves session name (--parent > existing match > generated {slot}-{oracle} where slot is a deterministic hash 10-89). Creates session/window as needed, sends engine command via send_text as MAW_SESSION_WINDOW={w} cd {cwd} && {engine}. Selects window on attach.

maw work

crates/maw-cli/src/core_impl/workspace_scaffold_commands.rs (dispatch L11, entry L367) + crates/maw-cli/src/core_impl/workon.rs (implementation, args L80)

Resolves a repo (via ghq, path, URL, or "."), optionally creates or reuses a git worktree for isolated agent work, then creates or reuses a tmux window (or session if outside tmux) and sends the configured engine command into it. Thin wrapper that delegates entirely to run_workon_command.

Worktree Support

Full support via --wt [slug] or positional [task]. Creates git worktrees under repo/agents/<slug> (nested, default) or as sibling dirs (legacy). Branch: agents/<slug>. Reuses existing worktrees by fuzzy match unless --fresh. --name provides a stable slug prefix. Numbering (1-feat, 2-feat) auto-increments on collision.

Engine Support

Via -e/--engine. Looks up the engine name in .maw config commands map (merged_config_value_in_dir). If found, uses that command string. If not, uses the raw engine string. Without -e: looks up window_name in commands map, falls back to commands.default, then falls back to "claude".

Tmux Interaction

Inside tmux: detects current session via display-message, creates new-window or reuses existing by name. Outside tmux: looks for existing session (exact match via has-session, then numbered fleet stem match like 188-reponame), creates with new-session -d if none found. Sends engine command via send-keys.

Copy-Paste Recipes: Codex Team Management

Spawn 1 coder (worktree-isolated)
# Creates agents/fix-auth worktree + tmux window + launches codex
maw work . fix-auth --wt -e codex
Spawn 1 coder (session, no worktree)
# Creates a new tmux session with codex in the current dir
maw new coder-1 -c "codex"
Spawn 5 coders (worktree loop)
# Each gets its own agents/coder-N worktree + branch
for i in 1 2 3 4 5; do
  maw work . coder-$i --wt --fresh -e codex
done
Spawn 5 coders (wake, oracle-based)
# Each wakes the oracle with a task-derived window name
for i in 1 2 3 4 5; do
  maw wake my-oracle --task coder-$i -e codex --new
done
Teardown 1 coder (kill tmux window)
# Kill a specific tmux window by name
tmux kill-window -t "coder-1"

# Or kill via wake --kill (if supported by your oracle)
maw wake my-oracle --task coder-1 --kill
Teardown all coders
# Kill all coder windows matching the pattern
for i in 1 2 3 4 5; do
  tmux kill-window -t "coder-$i" 2>/dev/null
done

# Clean up worktrees (if created with maw work --wt)
for i in 1 2 3 4 5; do
  git worktree remove agents/coder-$i --force 2>/dev/null
done

# Or kill the entire session
tmux kill-session -t "my-session"
